## 3. 분석 단위와 의존 구조

시행(obs1, obs2) ⊂ 시퀀스 ⊂ 블록 ⊂ 세션(측정 실행) ⊂ 참가자.

- obs1·obs2는 같은 시퀀스에서 **같은 색**이다 → 반드시 같은 fold.
- 같은 참가자의 세션이 **같은 seed**(2026-11-24까지의 모든 기록, P003 11-25 run-09 포함)면 블록 b의 색 순서가 세션 간에 동일하다("쌍둥이 블록"). 이 구조는 CV와 순열검정이 모두 존중해야 한다 (V-04).
- 이어하기 실행(`--start-block`)은 같은 seed 계획의 일부이며 블록 번호를 유지한다. 같은 시퀀스가 두 실행에 중복되면 하나만 사용한다(기존 P003 제안과 동일 원칙).

## 4. 데이터 분할

| 평가 | 외부 분할 | 그룹 정의 | 내부 분할(모델 선택) | 비고 |
|---|---|---|---|---|
| W1 참가자 내 · 세션 내 (확증 주분석) | 세션별 블록 5-fold (leave-one-block-out) | 블록(세션 내) | 학습 4블록 안에서 GroupKFold(블록) | 같은 세션 내 블록은 서로 다른 순서 → 쌍둥이 문제 없음. 세션별 결과 + 참가자 내 세션 평균 |
| W2 참가자 내 · 여러 세션 합침 (탐색) | leave-one-group-out | **같은 seed 세션 간에는 블록 번호**(쌍둥이 블록을 함께 제외), 다른 seed 세션 간에는 세션×블록 | 학습 그룹 안 GroupKFold | 저장된 결과(세션×블록 그룹)는 이 규칙을 따르지 않음 |
| X1 세션 간 일반화 | leave-one-session-out | 세션 | 학습 세션 안 GroupKFold | 같은 seed 세션 간 결과는 "스케줄 공유"로 표기. 서로 다른 seed 세션이 생기면 그것을 주 결과로 |
| X2 참가자 간 일반화 (탐색, 계획상 ≥4명) | leave-one-subject-out | 참가자 | 학습 참가자 안 GroupKFold | EA 등 라벨 미사용 정렬은 테스트 세션 데이터를 쓰는 transductive 방식임을 표기 |

공통 규칙: 스케일러·특징선택·xDAWN·정렬 행렬·증강·튜닝·스태킹 메타학습기는 외부 학습 fold 안에서만 fit (스태킹 내부 CV도 그룹 분할). 시행 내 하위 윈도우를 쓰면 같은 시행의 윈도우는 같은 fold.

추가 규칙 (제안, 결과 보기 전 확정):
- W1 최소 블록 수: 세션당 유효 블록 ≥ 4 (사전등록 코드 `train_svm.py --min-blocks` 기본값은 5). 미달 세션은 W1에서 제외하고 W2에서만 보고. 블록별 최소 유효 시행 수(예: 색별 ≥ 2시퀀스)도 함께 정한다.
- 부분 블록(실행 중단으로 일부 시퀀스만 있는 블록): 같은 시퀀스가 완전한 블록에 있으면 부분 블록을 제외. 없으면 해당 블록을 하나의 그룹으로 사용하고 표기.
- 한 녹화(`.db`)에 이벤트 파일이 둘인 경우(P08 1109a/b): 실행(run)별로 그룹을 나누되 같은 시퀀스 중복 여부를 먼저 확인.
- X1·X2 순열: 각 세션(참가자) 안에서 §6과 같은 시퀀스 단위·쌍둥이 공유 순열을 적용하고, 학습·테스트 세션 모두에 같은 규칙을 쓴다.

## 5. 지표와 집계

- **주 지표: (결정 필요 §11-A)** 사전등록 주지표는 **Balanced Accuracy(BA)** 다. 이번 연구 지시서는 Macro-F1을 주 지표 "후보"로 제시했다.
  권고: 확증 분석의 주 지표는 사전등록대로 BA를 유지하고, Macro-F1을 핵심 보조 지표로 함께 보고한다. (블록당 색별 6시퀀스로 균형 설계라 두 지표는 대체로 비슷하지만, 같지는 않다. 결과를 본 뒤 주 지표를 바꾸면 사후 조정이 된다.)
- 보조 지표: Macro-F1, Accuracy, 클래스별 Recall, MCC, 혼동행렬(행 정규화 + 원시 수).
- 참가자 내 집계: 외부 fold 예측을 모두 모아 1개 값(pooled) + fold별 분포를 함께 보고.
- 집단 집계: 참가자 평균(참가자당 동일 가중) + 참가자 수준 부트스트랩 10,000회 95% CI (사전등록). 참가자 4명 이하에서는 부트스트랩 CI가 불안정하므로 참가자별 결과를 반드시 함께 제시.

## 6. 우연 수준과 비교 기준

| 기준 | 방법 | 용도 |
|---|---|---|
| 균등 추측 | 33.33% | 참고선 |
| Dummy Classifier | `stratified`, `most_frequent`, `uniform` 각각을 같은 외부 분할로 평가 | 실제 비교 기준 |
| 순열 null (추론 기준) | 라벨을 **시퀀스 단위**로(obs1·obs2 함께), 각 블록 안에서 섞되 **같은 seed의 쌍둥이 블록에는 같은 순열**을 적용. 전체 외부 CV를 매번 재실행. 판정용 1,000회(최소 p ≈ 0.001), 탐색용 200회 | p값 |
| 이항 임계값 | 사용하지 않음 — CV에서 fold마다 모델이 달라지는 분산 때문에 실제 null이 iid 이항보다 넓다 (V-01 실데이터 1.14–1.29배, V-03b 독립 합성 시행에서도 1.11–1.28배). 시퀀스 쌍처럼 시행이 의존하면 더 넓어질 수 있다 | — |

## 7. 시드

- 외부 CV는 LeaveOneGroupOut이라 결정적이다.
- 확률적 요소(SVC probability, 증강 잡음, LR 등) random_state 목록: `[0, 1, 2, 3, 4]` — 결과는 5개 시드의 평균과 범위로 보고.
- 순열 시드: `0 … n_perm−1`. 합성 검증: V-03/V-04 스크립트의 고정 시드.

## 8. 탐색용 데이터와 최종 평가

- 2026-11-25까지 측정된 분석 가능 세션(sessions.csv '사용' 9개)은 이미 19개 파이프라인 비교·순열검정에 사용되었다. 제외된 기록(P001_1119, P02 11-03, P003 11-13 완주 기록 등)은 같은 seed이거나 품질·윤리 문제가 있어 독립 평가용으로 적합하지 않다 → **독립 평가에 쓸 수 있는 기존 데이터가 없다.** 기존 데이터는 탐색(개발) 데이터로만 쓴다.
- 탐색 단계의 반복 사용 편향: 최대 30회의 E-xx가 같은 995 시행을 재사용하므로 nested CV만으로는 적응적 재사용 편향이 남는다. 모든 KEEP 판정은 하나의 비교 집합(family)으로 보고 연구 영역별 다중비교 보정을 적용한다.
- 탐색 단계의 모델 선택은 nested CV로 추정한다(선택-인식 추정이지만 독립 평가는 아님).
- **독립 최종 평가 (결정 필요 §11-C)**: 프로토콜·파이프라인 동결 후 측정되는 데이터(변경3 규칙의 새 seed 세션, 신규 참가자)를 최종 평가 데이터로 지정하고, 동결된 파이프라인으로 **1회만** 평가한다. 그 결과는 추가 모델 탐색에 사용하지 않는다.
- 최종 평가의 성공 기준(동결 시 확정, 제안): 주 지표(§11-A), 참가자별 시퀀스 단위 순열검정 1,000회 단측 α = 0.05, 참가자 수에 대한 다중비교 보정(Holm), 집단 수준은 참가자별 결과 + 참가자 부트스트랩 CI. 최소 표본(제안): 새 seed 세션 ≥ 1개/참가자, 유효 블록 ≥ 4. 검출 가능 효과의 크기는 V-01의 null SD(2.6–5.9 %p)를 참고해 사전에 계산해 둔다.

## 9. 탐색 실험 채택 기준 (KEEP / DISCARD / INCONCLUSIVE / INVALID) — 제안값

- **INVALID**: 데이터 무결성 오류, 누수, 합성 null 보정 실패(아래 §10), 프로토콜 위반.
- **KEEP**: (a) 같은 fold에서 Baseline과 짝지은 검정 — 참가자별 시퀀스 단위·쌍둥이 공유 순열에 따른 짝지은 순열검정(또는 참가자별 BA 차이의 짝지은 부트스트랩) — 이 해당 연구 영역의 E-xx 수로 보정한 뒤 p < 0.05이고, (b) 참가자 4명 중 3명 이상에서 같은 방향(우연히 3명 이상일 확률 5/16 ≈ 0.31이므로 (a) 없이 단독 기준으로 쓰지 않음), (c) gray1·색 직전 대조가 null 95% 이하 유지, (d) 신호처리 관점의 설명 가능. 기준은 §11-A에서 정한 주 지표로 판단한다. (참고: 참가자별 null SD 2.6–5.9 %p이므로 '평균 개선 ≥ 2 %p' 같은 고정 임계값은 단독 기준으로 부적절.)
- **DISCARD**: 위 (a)를 만족하지 못하고 효과 추정이 0 근처.
- **INCONCLUSIVE**: 방향은 일관되나 참가자 간 불일치 또는 CI가 0을 넓게 포함.
- 모델 채택 여부와 학술적 가치는 따로 기록한다(성능 하락도 기록).

## 10. 누수 방지 검사 (모든 새 파이프라인에 필수)

1. **합성 null 보정**: `research/validation/v03_synthetic_leakage.py` 방식으로 색 정보가 없는 합성 데이터에서 평가한다. 선별 단계: 20회 반복, 검사한 파이프라인 수로 Bonferroni 보정한 단측 t 검정(예: 19개면 t > 3.1 수준)에서 1/3 초과가 아니면 통과. 초과하거나 Baseline과 비교할 파이프라인이면 200회로 확대해 평균의 95% CI가 1/3을 포함하거나 |평균 − 1/3| < 1 %p(동등성 범위)이면 통과. 200회에서도 실패하면 INVALID. (V-03 + V-03c는 기존 19개 파이프라인에 20회 선별 기준 '1/3 + 3 SE 이하'를 적용했고, V-03b는 핵심 ERP 2개(Baseline 포함)를 200회로 확인했다.)
2. **합성 민감도**: 작은 색 효과를 주입하면 BA가 상승해야 한다.
3. **gray1 대조**: 색이 화면에 없는 gray1 구간을 다음 색으로 라벨링 → null 수준이어야 한다. gray 시작 직후뿐 아니라 **색 직전 1 s(−1~0 s)** 도 검사한다. 색 순서는 이력으로 상당히 예측되므로(V-04b: 블록 내 이력 51.4%, 마지막 시퀀스 100%) 참가자의 기대 활동은 색 직전에 가장 클 것이다.
4. **자극 전 시간 구간 해독** (−0.2~0 s) → null 수준이어야 한다. 영위상 필터를 쓰면 자극 후 반응이 자극 전으로 번질 수 있다.
5. **이력 층화**: 해독 성능을 이력 예측이 맞는 시행과 틀린 시행으로 나눠 보고한다. 이력 예측이 맞는 시행에서만 성능이 높으면 현재 색이 아니라 기대·이력 정보를 해독한 것일 수 있다.

## 12. 평가 스크립트 (동결 대상)

- **현재 상태: 확정된 단일 평가 스크립트 없음.** §11 결정(주 지표, 포함 세션, 분할 규칙)이 스크립트 사양을 바꾸므로, 결정 전에는 작성하지 않았다.
- 확증 분석(W1) 후보: 사전등록 코드 `rgb-eeg-lab/scripts/train_svm.py` — 블록 단위 nested LOGO(외부·내부), BA·Macro-F1·MCC·혼동행렬, 시퀀스 단위 셔플 점검, 참가자 부트스트랩 CI, 최소 블록 수 규칙, LOSO를 이미 구현(합성 테스트 통과, T-01). 부족한 점: Dummy 기준, 1,000회 순열 null, Accuracy·클래스별 Recall 별도 출력, 실행 기록(run.json).
- 탐색 분석(W2·X1·X2) 공통 스크립트 사양(작성 예정 `research/protocol/evaluate.py`): 입력 = 데이터 매니페스트, 파이프라인 정의, 분할(W1/W2/X1/X2), 시드 목록 → 출력 = pooled·fold별 지표 전부(§5), 같은 fold의 Dummy 3종, §6 순열 null, 참가자 부트스트랩, run.json(명령·commit·패키지 버전·입력 해시·경고·오류). 합성 자기검증(§10.1–10.2)을 통과해야 동결.
- 동결 시 두 스크립트의 commit과 SHA-256을 §2 표에 기록한다.
